Features

Explore the core features of d-cron: distributed coordination, split-brain fencing, execution safety, and observability.

📄️Core Architecture

d-cron provides safe, single-leader cron-style job scheduling across an arbitrary number of horizontally-scaled application replicas using only PostgreSQL Session-Bound Advisory Locks.

📄️Split-Brain & Fencing

In distributed systems, GC pauses, heavy OS swapping, or temporary network partitions can cause a node to experience a split-brain state: a node thinks it is still the leader while a new leader has already been elected.

📄️Execution Safety & Retries

Production background job engines must be resilient against runtime panics, unhandled errors, and external timeouts. d-cron provides built-in safety mechanics to prevent crash cascading and ensure reliable task execution.

📄️Overlap & Missed Runs

In production environments, a long-running batch job may take longer than its scheduled trigger interval, or an application deployment/restart may cause a scheduled trigger time to be missed.

📄️Execution History Store

By default, d-cron operates with zero database tables. When compliance, auditing, missed-run catch-up, or dashboard monitoring requires durable tracking, d-cron provides an opt-in durable execution history store backed by PostgreSQL.

📄️Observability & Dashboard

d-cron provides deep observability across your distributed cron cluster, including an embedded Web Dashboard UI, Prometheus metrics, OpenTelemetry distributed tracing, webhook alert hooks, and an HTTP REST Admin API.

📄️Production & Kubernetes

d-cron is built natively for horizontal scaling in containerized production environments. Because coordination occurs at the database layer via PostgreSQL advisory locks, deployments require no custom Kubernetes CRDs, no statefulsets, and no RBAC permissions.
